# 学習ログ — 2026-05-21

## チャットUIアプリ開発を通じた学び

### React / Next.js 基礎

- **useContext + createContext**: グローバルな状態管理の仕組み。createContext → Provider → useContext の3ステップ。Provider で囲んだ子コンポーネント全体で値を共有できる
- **useCallback**: 関数をメモ化するフック。依存値が変わらない限り同じ関数を再利用する。子コンポーネントへの props 渡しや useEffect の依存配列で有用だが、ほとんどのケースでは不要
- **useRef + scrollIntoView**: DOM要素への参照を作り、scrollIntoView({ behavior: "smooth" }) でスムーズスクロールを実現。メッセージ一覧の末尾に空の div を配置し、メッセージ追加時に useEffect で自動スクロールする実装パターン
- **useEffect**: state の変更を検知して副作用を実行する。setState は非同期的なので、更新後の値を確認するには useEffect を使う
- **map によるリストレンダリング**: JSX内では for 文は使えない（文ではなく式が必要）。map を使い、key 属性を必ず付ける

### 型定義 (TypeScript)

- **string literal union 型**: `"gpt-4o" | "gpt-5.5-pro"` のように具体的な文字列で型を定義。型に含まれない文字列を使うとコンパイルエラーになる
- **型の追加忘れ**: 新しいモデルIDをリストに追加する際、型定義（OpenAILLMID）にも追加が必要
- **as によるキャストの活用**: Select の onValueChange は string を返すが、state の型が LLMID の場合は `as LLMID` でキャストする

### OpenAI API

- **Chat Completions vs Responses API の違い**:
  - Chat Completions (`/v1/chat/completions`): ステートレス。毎回全メッセージ履歴を送る
  - Responses (`/v1/responses`): ステートフル。`previous_response_id` で会話を繋げる。API側が履歴を保持
- **Responses API のレスポンス構造**: output 配列に `type: "reasoning"` と `type: "message"` が含まれる。メッセージ本文は `output.find(o => o.type === "message").content[0].text` で取得
- **previous_response_id による会話継続**: レスポンスの id を保存し、次のリクエストに渡すだけで文脈を維持できる。ただし OpenAI 側の保持期間（デフォルト30日）があるため、永続保存にはDB保存が必要
- **モデルの存在確認**: APIキーで利用可能なモデルは `/v1/models` エンドポイントで確認できる
- **API Route パターン**: クライアント → 自前の API Route → OpenAI API。APIキーはサーバー側のみで保持し、クライアントには露出させない

### shadcn/ui コンポーネント

- **ScrollArea**: Radix UI ベースのスクロールコンポーネント。OS間でスクロールバーの見た目を統一。flex-1 だけでは高さが確定しないため overflow-hidden の追加が必要な場合がある
- **Select**: Radix UI の Select プリミティブをラップ。value + onValueChange で制御コンポーネントとして使う。Portal でDOM外に描画されるため z-index の問題を回避

### 環境変数 (.env)

- `NEXT_PUBLIC_` プレフィックス付き → クライアント側でも使える
- プレフィックスなし → サーバー側のみ（APIキーなど秘密情報はこちら）
