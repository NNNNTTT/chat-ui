# 学習ログ — 2026-05-24

## Radix UI ScrollArea が flex レイアウトでスクロールしない問題

### 発生状況

`shadcn/ui` の `ScrollArea`（中身は Radix UI）を flex column な親の中で `flex-1 min-h-0` で使ったところ、コンテンツが溢れてもホイールスクロールが効かない。さらに「`position: absolute; inset: 0` で親を埋める」アプローチも効かなかった。

### 原因の本質

**Radix の `ScrollArea` Root は `style={{ position: "relative", ... }}` を _インラインスタイル_ で必ず設定する。** これを Tailwind のクラス（`absolute` など）では上書きできない（インライン > CSS クラスの specificity）。

Viewport は `size-full`（`height: 100%`）。`height: %` は親に「definite な高さ」がないと解決されず `auto` 扱いになる。すると Viewport がコンテンツと同じ高さに広がり、`overflow: scroll` が設定されていても overflow が発生せず、ホイールでスクロールできなくなる。

### 高さを「definite」にする条件

CSS の `height: 100%` がピクセル値に解決されるためには、親要素のいずれかが満たされている必要がある:

1. 親に明示的な `height` がある
2. 親が flex item で、flex 親に definite なサイズがある **かつ** 親に `overflow: hidden` 等が指定され BFC を確立している
3. 親が `position: absolute` で `top` / `bottom` 両方が指定されている

ScrollArea の場合、Radix が `position: relative` を強制するので 3 は不可。1 か 2 を満たす必要がある。

### 失敗したアプローチ

| アプローチ | 失敗理由 |
|---|---|
| `<ScrollArea className="absolute inset-0">` | Radix のインライン `position: relative` が勝ち、`absolute` が効かない。`inset: 0` は relative では位置オフセット 0 になるだけで親を埋めない |
| 親に `relative + flex-1 min-h-0`、ScrollArea に `absolute inset-0` | 同上。ScrollArea Root は relative のまま、内側 Viewport の `100%` が解決しない |
| ルートを `grid h-screen` + main に `h-full` | grid track の高さが内部 flex 子の `flex-1` 経由の `100%` 解決に弱く、ブラウザによっては Viewport まで高さが伝播しない |

### 正解パターン

旧コードで動いていた構成に戻したら一発解決した:

```tsx
<div className="flex h-screen overflow-hidden">           {/* root: flex */}
  <Sidebar .../>
  <main className="flex-1 flex flex-col min-w-0">         {/* main: flex-1 */}
    <Header className="shrink-0" />
    <ScrollArea className="flex-1 overflow-hidden">       {/* ★ */}
      <div>{...messages...}</div>
    </ScrollArea>
    <Composer className="shrink-0" />
  </main>
</div>
```

**ポイント:**

- ルートを `flex` にし、main を `flex-1`。grid + `h-full` チェーンを避ける
- ScrollArea Root に **`overflow-hidden`** を当てる。これは「コンテンツを隠す」目的ではなく、**BFC を作って flex item の高さを definite にする**ためのトリック
- これで Viewport の `size-full` がピクセル値に解決し、内部コンテンツが溢れたとき初めて Radix の `overflow: scroll` が機能する

### 学び

- **3rd party コンポーネントのインラインスタイルは Tailwind では上書きできない**。`...props.style` を後ろに spread している実装なら `style` prop 経由で渡せば上書き可能。クラスだけで戦わない
- **`overflow-hidden` には「クリップ」以外に「BFC を作る」という役割がある**。flex item + `height: 100%` の子要素という構成では、間に `overflow-hidden` が必要になることがある
- **percentage height は意外と脆い**。`h-full` を多用するときは、ルートからチェーンが切れていないか（`html → body → root → ... → 目的要素` 全てで高さが definite か）を意識する
- **動いていた旧コードがあるなら、まず diff を取る**。今回も「flex vs grid」「ScrollArea に直接 `overflow-hidden` を当てるか」の2点差が原因だった。新規実装での「綺麗な書き直し」が知らず知らずに動作条件を壊していた

### デバッグの進め方の反省

- 推測ベースで「`absolute inset-0` で埋めればいい」と何度もパッチを当てたが、根本原因（Radix のインラインスタイル）を読まないと正解にたどり着けなかった
- `node_modules` のソースを読むのを早めに行うべき。dist の minify されたコードでも `grep -n` で十分追える
- 「動いていた版との差分」をユーザーから提示されるまで気付けなかった。次回からは詰まったら **「以前動いていた状態に戻して差分を取る」** を最初の選択肢に入れる
